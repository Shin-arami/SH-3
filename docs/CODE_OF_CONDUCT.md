# SH-3 Code of Conduct

## Our Pledge

We are committed to making participation in the SH-3 project a welcoming, respectful, and collaborative experience for everyone.

Contributors, maintainers, reviewers, users, and community members are expected to act professionally and respectfully regardless of experience level, background, identity, nationality, or technical expertise.

Our goal is to build a high-quality open-source AI Operating System Framework through constructive collaboration.

---

# Our Standards

Examples of behavior that contributes to a positive environment include:

* Being respectful in discussions.
* Providing constructive technical feedback.
* Welcoming questions from contributors of all experience levels.
* Accepting feedback with professionalism.
* Focusing on technical solutions rather than personal opinions.
* Helping improve documentation, tests, and code quality.
* Respecting different approaches when discussing architecture or implementation.

Examples of unacceptable behavior include:

* Harassment or personal attacks.
* Discrimination of any kind.
* Trolling or deliberately disruptive behavior.
* Insults or inflammatory language.
* Publishing private information without permission.
* Spam or intentionally misleading contributions.
* Repeatedly ignoring established project guidelines.

---

# Project Principles

Technical discussions should always follow the SH-3 philosophy.

* Everything Event Driven
* Everything Replaceable
* Everything Typed
* Everything Testable

Disagreements should be resolved through technical reasoning, documented proposals, benchmarks, RFCs, and objective discussion.

---

# Communication

Please keep discussions:

* Professional
* Respectful
* Technical
* Evidence-based

When proposing changes:

* Explain the motivation.
* Describe the expected benefit.
* Consider compatibility.
* Be open to alternatives.

---

# Responsibilities of Maintainers

Project maintainers are responsible for:

* Reviewing contributions fairly.
* Explaining technical decisions when practical.
* Maintaining project quality.
* Enforcing this Code of Conduct consistently.
* Prioritizing the long-term health of the project.

Maintainers may edit, reject, or request changes to contributions that do not meet project standards.

---

# Reporting Issues

If you experience or witness unacceptable behavior, please report it privately to the project maintainers.

Reports should include:

* Description of the incident
* Relevant links or screenshots (if available)
* Date and time
* Any additional context

All reports will be handled respectfully and confidentially whenever possible.

---

# Enforcement

Project maintainers may take appropriate actions, including:

* Requesting changes in behavior.
* Removing inappropriate comments or content.
* Temporarily restricting participation.
* Permanently banning users who repeatedly violate this Code of Conduct.

Enforcement decisions are made to protect the project and its community.

---

# Scope

This Code of Conduct applies to:

* GitHub Issues
* Pull Requests
* Discussions
* Documentation
* Code Reviews
* Project-related communication channels
